Notes for working on the code. Start with the [README](../README.md) for
setup and status, then [spec.md](spec.md) for the design, and
[m1-progress.md](m1-progress.md) (iOS app and push) and

## Generated and private files

These are git-ignored: `deploy/switchboard.yaml`, `deploy/config/`,
`deploy/appservices/`, `deploy/secrets/`, `deploy/.env`,
`deploy/compose.bridges.yml`, `deploy/.docker/`, `app/tool/local.env` and
`app/ios/Flutter/Local.xcconfig`.
`sb` writes all of the `deploy/` ones; nothing in them should be edited by
hand except `switchboard.yaml`, before `sb init`.

## Backend

```sh
make sb        # bin/sb
make test      # go vet and go test in sb/
```

- `sb` uses its own Docker config (`deploy/.docker`, no credential store),
  because every image is public and Docker Desktop's credential helper can
  hang on a Keychain prompt when nobody is at the Mac. It takes the Docker
  host from your current context.
- `sb render` re-renders the generated configs without restarting anything;
  `sb compose ...` runs `docker compose` in `deploy/` with the right files;
  `sb logs [SERVICE]` follows logs.
- `sb test` checks Synapse, the Hub and each bridge through Caddy's local port
  (`http://127.0.0.1:8080`). Its "bot answers a command" check fails for
  bridges that already have a management room (it sends an unprefixed `help`
  in a new DM, which those bots ignore): a fault in the test, not the bridge.
- Bridges built here (`build:` in `bridges.yaml`) are `bridges/signal` and
  `bridges/matrix`. When bumping mautrix-signal's tag, check whether each
  patch in `bridges/signal/patches` is still needed; each one's header says
  where it came from.
- For iOS push, Synapse calls the Hub, which drops pushes for messages sent
  more than two minutes before their chat was created (history a bridge
  imports on linking) and passes the rest to Sygnal. At startup the Hub also
  turns off the owner's `.m.rule.invite_for_me` push rule: bridges invite you
  to every chat they create, and each invite would otherwise be a push.
- If Docker Desktop can't restart a container that was killed (for example
  out of memory, with `AlreadyExists: task … already exists`),
  `sb compose up -d --no-deps --force-recreate <service>` brings it back.

## App

The sign-in screen's default server is a build-time define,
`--dart-define=SB_DEFAULT_SERVER=...`; without one the field starts empty.
The build scripts (`app/tool/sim-build.sh`, `install-iphone.sh`,
`testflight.sh`) and `packaging/arch/PKGBUILD` take it from the
`SB_DEFAULT_SERVER` environment variable, or else from `app/tool/local.env`:

```sh
echo 'SB_DEFAULT_SERVER=switchboard.example.ts.net' > app/tool/local.env
```

In `app/`, `flutter run --dart-define-from-file=tool/local.env` reads the same
file.

```sh
cd app
flutter test                            # unit, widget and golden tests
flutter_rust_bridge_codegen generate    # after changing core/src/api
```

- Keep private structs in `core/src/api` marked `#[frb(ignore)]` or out of
  that module, or the generator exposes them.
- The goldens in `app/test/goldens` are macOS renders; on Linux two of them
  differ by a few per cent from anti-aliasing.
- Debug builds compile the Rust dependencies at `opt-level = 3`; unoptimised,
  the store's key derivation takes about 40 s at first sign-in.
- `core/target` grows large (tens of GB). Delete it when space is short.
- Unread counts come from the SDK's counting on the device
  (`num_unread_notifications`, `num_unread_mentions`). Synapse's sliding sync
  always sends 0 for `notification_count` and `highlight_count`.
- The inbox is sorted in Dart by the newest message's send time
  (`byNewestMessage`), not the SDK's order, because Synapse counts a chat's
  creation and imported history as activity.
- The room list syncs one event per chat, so after time away a chat whose
  newest event isn't a message (a reaction, a delivery receipt) would keep an
  old preview and place. `watch_gaps` in the core fetches such chats' history
  back to a message after each sync.

### iOS

- `app/tool/sim-build.sh` makes a debug Simulator build that signs in by
  itself with the owner's password from `deploy/secrets`.
- `SB_SIM=<udid> app/tool/sim-shot.sh /accounts out.png` installs the last
  Simulator build, opens it at a route and takes a screenshot. Debug builds
  open at the route in `dev_route` in the app's support directory once.
- `app/tool/testflight.sh` archives a release with the newest side-by-side
  Xcode 26 or later (App Store Connect takes only iOS 26 SDK builds) and
  uploads it. Its builds push through APNs production
  (`SB_APNS_PRODUCTION=true`); development-signed builds use the sandbox.
- `ios/Runner/PrivacyInfo.xcprivacy` declares the required-reason APIs for
  the app, the Rust core and the media_kit frameworks. App Store Connect
  rejects an upload that uses one it doesn't list.
- The notification extension must not use `async let`: on iOS 26 the release
  build aborts in the concurrency runtime, which the Mac doesn't reproduce.
  `app/tool/test-notification-service.sh` checks the extension's wording on
  macOS. For crashes on a phone, `xcrun devicectl device info files --device
  <id> --domain-type systemCrashLogs` lists `NotificationService-*.ips`, and
  `xcrun devicectl device copy from` fetches one.
- A notification from a sender with a picture is a communication
  notification, which is what has iOS draw the picture where the app's icon
  would be. That takes the Communication Notifications capability
  (`com.apple.developer.usernotifications.communication` in
  `Runner.entitlements`; automatic signing adds it to the profile) and
  `INSendMessageIntent` under `NSUserActivityTypes` in the app's
  `Info.plist`. Without them iOS shows the same text with the app's icon,
  which is also what a sender with no picture gets. iOS words a
  communication notification itself, from the intent and not from the title
  and subtitle: the sender's name, with the intent's group name under it
  when the intent has more than one recipient. That line carries the group
  and the network ("Mum" over "Family · Signal", "Alice" over "WhatsApp").
- Settings › Hide sender in notifications is a file in the app's support
  directory, so a fresh install starts with it off. The notification
  extension can't read that, so the app keeps a copy in the keychain group
  the two share (`setHideSender` on the `switchboard/push` channel), written
  at each launch and each change. With it on, a notification says "New
  message" in place of the sender and the chat and keeps the app's icon.
  `SB_HIDE_SENDER=1 app/tool/test-notification-service.sh` renders a real
  event that way.
- `app/tool/install-iphone.sh` builds a release and installs it with roamrun,
  a separate tool the author uses to install over Tailscale. It is optional:
  `flutter run --release` or Xcode installs on a phone without it.

The signing team isn't in the project: every target takes it from
`app/ios/Flutter/Local.xcconfig` (git-ignored, read by `Signing.xcconfig`
next to it), which holds one line, `DEVELOPMENT_TEAM = <your team ID>`.
Choosing a team in Xcode instead writes it into the project file. The bundle
ID `com.richarddraycott.switchboard` is written into the project. To build
under your own, change it in `app/ios/Runner.xcodeproj/project.pbxproj`,
`app/ios/Runner/Info.plist`, both `.entitlements` files under `app/ios`,
`app/ios/Runner/SharedSession.swift` (the shared keychain group) and
`app/lib/src/state/push.dart` (Sygnal's app IDs), then pass the new ID to
`sb push`. The scripts in `app/tool` use it too. On Linux it is the app ID,
in `app/lib/src/desktop.dart`, `app/linux/CMakeLists.txt` and the desktop
file in `app/linux/packaging`.

### Linux

- The build needs rustup's `stable` toolchain at 1.99.1 or later, because
  cargokit builds the core with `rustup run stable`.
- Desktop notifications carry the sender's picture as raw pixels (the
  notification spec's `image-data`), and otherwise the app's icon from the
  bundle (`assets/icon/switchboard-256.png`): for a sender with no picture,
  one that can't be fetched, and every notification while Settings › Hide
  sender in notifications is on. `ChatNotifications` in
  `app/lib/src/desktop.dart` decides; `app/test/chat_notifications_test.dart`
  drives it with a stand-in for the notification server.
- `app/tool/linux-shot.sh /accounts out.png 1280x800` opens a route in the
  debug build under Xvfb and takes a screenshot.
- `app/tool/linux-web-login-test.sh` runs the real WebKitGTK sign-in window
  against a local page under Xvfb.
- To reach the server from a machine on another tailnet, the core honours
  `HTTPS_PROXY`.

## Live tests

Some core tests run against a real server and are ignored by default:

```sh
cd core
SB_TEST_SERVER=https://switchboard.<tailnet>.ts.net \
SB_TEST_USER=<your username> \
SB_TEST_PASSWORD=$(cd ../deploy && ../bin/sb secret get ADMIN_PASSWORD) \
SB_TEST_ROOM='<test room id>' cargo test --lib -- --ignored
```

`SB_TEST_USER` is the account's localpart (`alice` for
`@alice:switchboard.internal`). A test fails at once, naming the variable, if
one it needs is unset. They send, edit and delete messages in the test room,
so point them at a room made for it.

## Demo backend and screenshots

`app/tool/demo/demo.sh up` starts a throwaway backend for screenshots: its
own Synapse and Caddy containers (`sbdemo-*`, on their own Docker network and
volume), the Hub from `sb/` on the host, stand-ins for the bridges'
provisioning APIs, and a seed of made-up people and chats badged as
WhatsApp, Signal, Telegram, Slack, Discord, Instagram and Matrix. It serves
plain HTTP on `http://localhost:18480` and prints the demo account's
password. It doesn't touch a Switchboard install, and `demo.sh down` removes
everything it made.

Build the app against it, sign in, then send the unread messages:

```sh
cd app
flutter build ios --simulator --debug \
  --dart-define=SB_DEFAULT_SERVER=http://localhost:18480 \
  --dart-define=SB_DEV_USER=alex --dart-define=SB_DEV_PASSWORD=<printed password>
xcrun simctl status_bar <udid> override --time 9:41 --batteryState charged \
  --batteryLevel 100 --cellularBars 4 --wifiBars 3
SB_SIM=<udid> tool/sim-shot.sh / /tmp/inbox.png 40    # signs in and syncs
tool/demo/demo.sh unread
SB_SIM=<udid> tool/sim-shot.sh /accounts /tmp/accounts.png 15
```

The app counts unread messages from the events it has, and a first sync
brings only each chat's newest one, so `demo.sh up` holds the unread
messages back until `demo.sh unread`, sent while the app is open. The seed
backdates messages so the newest is at 09:40 today, to match the status bar.

The images in `docs/images` are half-size PNGs from iPhone 16 Pro and iPad
Pro 13-inch Simulators on iOS 18.6. On the iOS 26.3 Simulator, a debug build
from Xcode 16.4 drew emoji as missing-glyph boxes.
